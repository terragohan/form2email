{% extends "guide-base.html" %} {% block heading %}A contact form that emails you{% endblock %} {% block standfirst %}The classic name / email / message form — on your contact page or in your footer — with every message delivered to your inbox.{% endblock %} {% block about %}

Every website needs a way for visitors to get in touch, and a contact form beats publishing your email address: no spam harvesters scraping it, no mailto: awkwardness, and the message arrives with the sender's address already set as reply-to.

If your site is static — plain HTML on any host — it can't receive the form POST itself. Form2Email receives it and emails you the message. There is no PHP, no server code, and no account to create.

{% endblock %} {% block example %} <form action="{{ settings.base_url.rstrip('/') }}/f/your-token" method="post"> <label for="name">Name</label> <input id="name" name="name" required> <label for="email">Email</label> <input id="email" name="email" type="email" required> <label for="message">Message</label> <textarea id="message" name="message" rows="6" required></textarea> <!-- optional: your own thank-you page after submit --> <input type="hidden" name="_redirect" value="https://yoursite.com/thanks"> <button type="submit">Send message</button> </form> {% endblock %} {% block example_notes %}

That's the whole integration. The form works with or without JavaScript, on any host that can serve an HTML page. Style the fields however you like — only the action, method="post", and the input name attributes matter to Form2Email.

{% endblock %} {% block mapping %}

Each submission becomes one email to your destination address:

  • Reply-To is the visitor's email, so hitting reply answers them directly.
  • name and message appear in the body.
  • Any other fields you add (a subject, a phone number, anything) are listed as additional fields.

With _redirect set, the visitor's browser is sent to your thank-you page after a successful submit. Without it they get a small JSON response — fine for JavaScript-driven forms, less friendly for plain HTML.

{% endblock %} {% block tips %}
  • Keep it to three fields. Name, email, and message are enough — every extra field costs you messages.
  • Make the button say what happens: "Send message", not "Submit".
  • Use the _redirect field so visitors land on a real thank-you page instead of a JSON response.
  • Add {{ settings.mail_from }} to your contacts so the verification and submission emails don't land in spam.
{% endblock %} {% block limitations %}
  • A contact form is always-on, so remember the endpoint expires {{ settings.default_ttl_days }} days after verification — extend it for free from your manage page, or ask the operator for a permanent endpoint.
  • Submissions are accepted only from the exact domain you registered. If your site answers on both yoursite.com and www.yoursite.com, register the one your form is served from (or create one endpoint per hostname).
  • No file attachments — file inputs are dropped. Ask for a link instead.
  • Spam protection is origin checks plus per-IP rate limits with backoff; there is no CAPTCHA or honeypot yet.
