{% extends "guide-base.html" %} {% block heading %}An RSVP form that emails you every reply{% endblock %} {% block standfirst %}Attendance, guest counts, and meal choices for your workshop, meetup, wedding, or community event — each RSVP delivered to your inbox as it arrives.{% endblock %} {% block about %}

Event pages need an answer to one question: who's coming? Whether it's a workshop with twelve seats, a meetup that needs a headcount for pizza, or a wedding collecting meal choices, the replies all look the same — a name, a yes or no, and a few details.

If your event page is static HTML, it can't receive the form POST itself. Form2Email receives it and emails you each RSVP, so the headcount builds up in your inbox without a spreadsheet, a database, or an account to create.

That's the whole integration. The form works with or without JavaScript, on any host that can serve an HTML page. Style the fields however you like — only the action, method="post", and the input name attributes matter to Form2Email.

{% endblock %} {% block mapping %}

Each RSVP becomes one email to your destination address:

  • Reply-To is the guest's email, so hitting reply reaches them directly if plans change.
  • name appears in the body.
  • attending, guests, meal, and notes are listed as additional fields.

With _redirect set, the guest's browser is sent to your page after a successful submit. Without it they get a small JSON response — fine for JavaScript-driven forms, less friendly for plain HTML.

{% endblock %} {% block tips %}
  • Ask for dietary needs and accessibility requirements in the notes field rather than adding more inputs — one free-text box covers requests you didn't anticipate.
  • One email per RSVP makes headcounts easy: count the "yes" replies in your inbox, or filter on attending: yes with your mail client's search.
  • Point _redirect at a details page with the venue address, start time, and parking info — guests confirm their RSVP worked and get the practical details in one step.
  • Say on the page that no confirmation email is sent; guests only hear from you if you reply.
  • Add {{ settings.mail_from }} to your contacts so the verification and RSVP emails don't land in spam.
{% endblock %} {% block limitations %}
  • Timing matters: the endpoint expires {{ settings.default_ttl_days }} days after verification. If your event is further out than that, extend it from your manage page so it's still alive on the event date — extensions are free, unlimited, and revive an expired endpoint.
  • Submissions are accepted only from the exact domain you registered. If your event page answers on both yoursite.com and www.yoursite.com, register the one your form is served from (or create one endpoint per hostname).
  • Guests get no automatic confirmation email — Form2Email only emails you. Put the key details on the page itself or the _redirect target.
  • No file attachments — file inputs are dropped. Ask for a link instead.
  • Spam protection is origin checks plus per-IP rate limits with backoff; there is no CAPTCHA or honeypot yet.
