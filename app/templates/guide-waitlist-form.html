{% extends "guide-base.html" %} {% block heading %}A waitlist form that emails you every signup{% endblock %} {% block standfirst %}One email field on your coming-soon page — each signup lands in your inbox, so you can launch to a list instead of to silence.{% endblock %} {% block about %}

Before your product ships, the landing page has one job: collect the email addresses of people who want to hear "we're live". A waitlist form is a contact form reduced to its minimum — usually a single email input and a button — because every extra field loses signups.

A coming-soon page is often a static HTML file on any host, which can't receive the form POST itself. Form2Email receives each signup and emails it to you. There is no list software to run and no account to create.

{% endblock %} {% block example %} <form action="{{ settings.base_url.rstrip('/') }}/f/your-token" method="post"> <label for="name">Name <small>(optional)</small></label> <input id="name" name="name" autocomplete="name"> <label for="email">Email</label> <input id="email" name="email" type="email" autocomplete="email" required> <!-- optional: your own thank-you page after submit --> <input type="hidden" name="_redirect" value="https://yoursite.com/thanks"> <button type="submit">Join the waitlist</button> </form> {% endblock %} {% block example_notes %}

That's the whole integration. Drop the name field if you want the email-only version — only the action, method="post", and the input name attributes matter to Form2Email; styling is entirely up to you.

{% endblock %} {% block mapping %}

Each signup becomes one email to your destination address:

  • Reply-To is the visitor's email, so you can answer a signup directly.
  • email and the optional name appear in the body; any other fields you add are listed as additional fields.
  • Entries are also stored per endpoint, so a lost email isn't a lost signup — but there is no list export or newsletter-sending feature.

With _redirect set, the visitor's browser is sent to your thank-you page after a successful submit. Without it they get a small JSON response — fine for JavaScript-driven forms, less friendly for plain HTML.

{% endblock %} {% block tips %}
  • Email-only, above the fold, converts best. Add the name field only if you will actually use it in launch emails.
  • Make the button say what happens: "Join the waitlist", not "Submit".
  • Use the _redirect field so new signups land on a real thank-you page — a good place to ask them to share the page.
  • Add {{ settings.mail_from }} to your contacts so the verification and signup emails don't land in spam.
  • Send the launch announcement from your own mail account — Form2Email delivers signups to you, it doesn't email your visitors.
{% endblock %} {% block limitations %}
  • A waitlist typically runs for weeks or months, but the endpoint expires {{ settings.default_ttl_days }} days after verification — extend it for free from your manage page as often as you like (extending also revives an expired endpoint), or ask the operator for a permanent endpoint.
  • There is no double opt-in or confirmation email to the visitor — Form2Email only ever emails you, the endpoint owner.
  • Submissions are accepted only from the exact domain you registered. If your landing page answers on both yoursite.com and www.yoursite.com, register the one your form is served from (or create one endpoint per hostname).
  • Spam protection is origin checks plus per-IP rate limits with backoff; there is no CAPTCHA or honeypot yet.
