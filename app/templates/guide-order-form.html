{% extends "guide-base.html" %} {% block heading %}An order form without shop software{% endblock %} {% block standfirst %}A maker selling a few items, a bakery taking pre-orders, a flyer with an order form — the order details arrive in your inbox and you take it from there.{% endblock %} {% block about %}

A full shop system is overkill when you sell three things. If your product list fits in a dropdown, a plain HTML form can collect the order: who wants it, what they want, how many, and where it goes. No cart, no checkout plugin, no monthly fee for software you barely use.

Form2Email emails you each order as it comes in, with the customer's address set as reply-to. You confirm the order and arrange payment yourself — an invoice, a payment link, or cash on pickup.

That's the whole integration. The form works with or without JavaScript, on any host that can serve an HTML page. Style the fields however you like — only the action, method="post", and the input name attributes matter to Form2Email.

{% endblock %} {% block mapping %}

Each submission becomes one email to your destination address:

  • Reply-To is the customer's email, so hitting reply confirms the order with them directly.
  • name and address appear in the body.
  • product, quantity, notes, and any other fields you add are listed as additional fields.

With _redirect set, the customer's browser is sent to your page after a successful submit — a good place to explain when they'll hear from you and how payment works. Without it they get a small JSON response (Form2Email answers with a 303 redirect when _redirect is present, JSON otherwise).

{% endblock %} {% block tips %}
  • Keep the product list short enough for a <select> — a handful of options. If customers need to browse dozens of items, you want a shop, not a form.
  • Confirm every order by replying to the email you receive — reply-to is already set to the customer. Since Form2Email never emails the customer itself, your reply is the only confirmation they get.
  • Point _redirect at a page that explains what happens next: when you confirm, how long delivery takes, how payment works.
  • Make the button say what happens: "Place order", not "Submit".
  • Add {{ settings.mail_from }} to your contacts so the verification and order emails don't land in spam.
{% endblock %} {% block limitations %}
  • No payment processing. Form2Email emails you the order details and you handle payment separately — an invoice, a payment link, or in person. Never ask for card numbers in the form.
  • Not suited to high-volume catalogs: no stock tracking, no cart, no order numbers beyond what you write yourself. If orders outgrow your inbox, it's time for real shop software.
  • An order form is always-on, so remember the endpoint expires {{ settings.default_ttl_days }} days after verification — extend it for free from your manage page (extending also revives an expired endpoint), or ask the operator for a permanent endpoint.
  • Submissions are accepted only from the exact domain you registered. If your site answers on both yoursite.com and www.yoursite.com, register the one your form is served from (or create one endpoint per hostname).
  • No file attachments — file inputs are dropped. If customers need to send a reference photo, ask for a link instead.
