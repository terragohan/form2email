{% extends "guide-base.html" %} {% block heading %}Job applications that land in your inbox{% endblock %} {% block standfirst %}A name / email / résumé-link form on your careers page — every application arrives as an email you can answer by hitting reply.{% endblock %} {% block about %}

A small company hiring for one or two roles doesn't need an applicant-tracking system. It needs applications to reach the person doing the hiring — with the candidate's address already set as reply-to, and no spreadsheet or ATS subscription in between.

Careers pages are usually static, and a static page can't receive the form POST itself. Form2Email receives it and emails you the application. There is no server code to run and no account to create.

{% endblock %} {% block example %} <form action="{{ settings.base_url.rstrip('/') }}/f/your-token" method="post"> <label for="name">Name</label> <input id="name" name="name" required> <label for="email">Email</label> <input id="email" name="email" type="email" required> <label for="role">Role</label> <select id="role" name="role" required> <option value="">Choose a role…</option> <option value="product-designer">Product designer</option> <option value="backend-engineer">Backend engineer</option> </select> <label for="resume">Résumé or portfolio link</label> <input id="resume" name="resume" type="url" placeholder="https://…" required> <label for="message">Cover note</label> <textarea id="message" name="message" rows="6" required></textarea> <!-- optional: your own thank-you page after submit --> <input type="hidden" name="_redirect" value="https://yoursite.com/thanks"> <button type="submit">Apply</button> </form> {% endblock %} {% block example_notes %}

Style the fields to match your careers page — only the action, method="post", and the input name attributes matter to Form2Email. Note that the résumé field is a URL input, not a file input; see Limitations for why.

{% endblock %} {% block mapping %}

Each application becomes one email to your destination address:

  • Reply-To is the candidate's email, so hitting reply reaches them directly.
  • name and the message cover note appear in the body.
  • role and the resume link are listed as additional fields, along with anything else you add.

With _redirect set, the candidate's browser is sent to your thank-you page after a successful submit. Without it they get a small JSON response — fine for JavaScript-driven forms, less friendly for plain HTML.

{% endblock %} {% block tips %}
  • Hiring for one role? Drop the select and name the role in the page copy. For several openings, keep the select — or run one form per role so applications arrive pre-sorted.
  • Add screening questions as extra fields — "earliest start date", "authorised to work where the role is based?", salary expectations. You get up to 20 extra fields of 1,000 characters each, and they all land in the same email.
  • Reply-to is the candidate's address, so answering an application is just hitting reply — no copy-pasting addresses into your mail client.
  • Use the _redirect field so applicants land on a real thank-you page and know the application went through.
{% endblock %} {% block limitations %}
  • File uploads don't work: an input type="file" is silently discarded. That's why the example asks for a résumé link — have candidates point to LinkedIn, GitHub, a personal site, or a shared folder.
  • A careers page is easy to forget once the role is filled, so remember the endpoint expires {{ settings.default_ttl_days }} days after verification — extend it for free from your manage page (extending also revives an expired endpoint), or ask the operator for a permanent endpoint.
  • Submissions are accepted only from the exact hostname you registered. If the careers page lives on careers.yoursite.com, register that subdomain, not yoursite.com.
  • The cover note tops out at 20,000 characters and each extra field at 1,000 — plenty for a note, but ask for the CV as a link rather than pasted text.
  • Spam protection is origin checks plus per-IP rate limits with backoff; there is no CAPTCHA or honeypot yet.
